# Turnstile core

The port and everything that is the same for every adapter.

- `Turnstile`: the port. `authorize`, its raising form, `check`, `batch`, `filter`, `scope`, `explain`, and `review` delegate to `Turnstile.Port`, which resolves the configuration, reads the ledger head, asks the adapter, denies an unknown subject kind before asking and an unreachable engine after, stamps a `Turnstile.Decision`, and emits the call as one telemetry span named for the subject's kind.
- `Turnstile.Adapter`: the behaviour an adapter implements: `authorize`, `check`, `batch`, `scope`, and the optional `explain` and `around_query`, plus `requires_ledger/0`, `scope_cap/0`, and an options schema.
- The values that cross the port: `Turnstile.Subject`, `Turnstile.Object`, `Turnstile.Environment`, `Turnstile.Answer`, `Turnstile.Scope`, `Turnstile.Explanation`, `Turnstile.Decision`, `Turnstile.Reason`, `Turnstile.PolicyVersion`, `Turnstile.FactEvent`, `Turnstile.Exemption`, and the errors under `Turnstile.Error`.
- The values that cross the port share `Turnstile.Edge`: `to_map/1` and `from_map/1` on each struct, over one field specification per struct.
- `Turnstile.Ledger` and `Turnstile.Projection`: the behaviours behind the ledger and behind an adapter's state; `Turnstile.Ledger.Memory` and `Turnstile.Adapter.Fake` are the in-memory implementations tests bind. The fake's rules are a table in an `Agent`, one per test, and a table told to fail answers every call with an engine error. `Turnstile.Ledger.Fold` folds events into the facts they leave, as a whole, up to a position, or at a time.
- `use Turnstile.Schema`: the fact mapping, column by column, from an application's schemas to the four fact kinds.
- `use Turnstile.Repo`: the seam. `Turnstile.Repo.Surface` lists every `Ecto.Repo` function in one of four buckets; the overrides hand each query, write, and raw call to `Turnstile.Repo.Seam` with the `turnstile:` option, a decision or an exemption, resolved into a `Turnstile.Repo.Mediation`. A call on a protected schema that carries neither raises `Turnstile.Error.Unmediated` before any SQL; a write to a fact schema re-reads the row under the ledger's lock and appends its fact events in the same transaction.
- `Turnstile.Conformance.RepoCase`: the test that diffs the surface against a repo's exports and calls every non-plumbing function on a protected schema without a decision.
- `Turnstile.Credo.NoRawSQL` and `Turnstile.Credo.UnmediatedRepo`: the checks that keep raw SQL and unmediated repos out of `lib`.
- `Turnstile.Config`: the one configuration struct, validated once at boot; `Turnstile.Test.with_config/1,2` overrides it per process in tests.
- `Turnstile.Conformance`: the scenario table, the `scenario` macro, and `Turnstile.Conformance.AdapterCase`, the Tier 1 template every adapter, in this repository or outside it, proves itself against: the port's invariants as properties over `Turnstile.Conformance.Gen`, the shape tests of ledger mode none, the fail-closed case, the revocation-latency template, and the projection cases. An adapter that keeps state of its own seeds it through `Turnstile.Conformance.Seed`; a projection under test exposes `Turnstile.Conformance.Projected`. Core's test support holds the neutral fixture, `Turnstile.Fixture`, and its `World`.
- `Turnstile.Test.Cluster`: the ephemeral Postgres cluster `mix test` starts, and the Mox mock of `Turnstile.Clock` the conformance template stubs. `Turnstile.Test.queries/2` lists the SQL a function ran for the shape tests.

`glossary.md` defines the words this package owns. Core's `lib` depends on `ecto` and `nimble_options`; `ecto_sql` and `postgrex` serve its own tests only, and Boundary checks that no call from `lib` reaches them.
