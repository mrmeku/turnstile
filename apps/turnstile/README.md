# Turnstile

The port and everything that is the same for every adapter: the four functions an application calls, the behaviour an adapter implements, the seam that keeps the log complete, the three events, and the conformance suites. `docs/design.md` says why each is shaped as it is; this page says what is here.

- `Turnstile`: the port. `authorize/4`, `check/4`, `scope/4`, and `review/5` delegate to `Turnstile.Port`, which resolves the configuration, denies an unknown subject kind before asking the adapter and an unreachable engine after, stamps a `Turnstile.Decision`, and publishes the call as one `[:turnstile, :decision]` event. `review` asks `scope` once per subject under one operation id and returns the rule and the decision of each, so the reviewer's query runs under the subject it reports on.
- `Turnstile.Adapter`: the behaviour. `decide/5` answers one subject, operation, and object; `scope/5` answers a rule over an object type as `{dynamic, answer}`; `scope_cap/0` says how many objects a rule can name, or `:none` where the database runs it. Optional: `around_query/3`, for an adapter whose rules read session state; `options_schema/0`, validated at boot; `settle/0`, for an adapter with state of its own to bring into step before a test reads it.
- The values that cross the port: a subject as a `{kind, id}` tuple, an object as a `{type, id}` tuple, an environment as a map of the caller's facts with `now` beside them from the configured clock, `Turnstile.Answer`, `Turnstile.Decision`, `Turnstile.PolicyVersion`, `Turnstile.Exemption`, and the one exception `%Turnstile.Error{reason, detail}`. An adapter answers one `%Turnstile.Answer{verdict, reason, version, meta}`.
- `use Turnstile.Schema`: what a schema states about itself. `object_type/1` makes it protected, `carries/1` names the associations a parent's decision covers, `audited/1` says what kind of thing its rows are, and `fact/2` and `relationship/1` map its columns to the three fact kinds, which is what makes a change to them a change event.
- `use Turnstile.Repo`: the seam. `core/surface.ex` lists every `Ecto.Repo` function in one of four buckets; the overrides hand each query, write, and raw call to `adapter/seam.ex` with the `turnstile:` option, a decision or an exemption, which `core/mediation.ex` resolves into a mediation. A call on a protected schema that carries neither raises `%Turnstile.Error{reason: :unmediated}` before any SQL, because it would be an unlogged read or write. A single-row write to an audited schema publishes its change event inside the write's transaction through `Turnstile.Change`; a mediated read publishes its access event through `Turnstile.Access` once the rows are back. `use Turnstile.Repo, role: :owner` is the library's own channel, exempt on every call and recording nothing.
- `Turnstile.Config`: the one configuration struct, `adapter`, `clock`, and `caps`, validated once at boot. `Turnstile.Test.with_config/1,2` overrides it per process in tests, read through `$callers`.
- `Turnstile.Conformance`: the suite. `Turnstile.Conformance.AdapterCase` is the template every adapter, in this repository or outside it, proves itself against: one law per requirement line of `docs/conformance.md` §2, named by id and sentence, over a world the adopter's `Turnstile.Conformance.World` describes and `Turnstile.Conformance.Gen` draws from. `Turnstile.Conformance.Seed` loads a world into an adapter's own state; `Turnstile.Conformance.Versions` publishes, tightens, and restores a policy version. `Turnstile.Conformance.Law` holds the law table as data, and the freeze test holds it to the document. `Turnstile.Conformance.RepoCase` holds a mediated repo to the surface and to the guarantees E1 to E5 of `docs/events.md` §5.
- `Turnstile.Test`: what a test needs beside a case template. `Turnstile.Test.Fake` is the in-memory adapter, an `Agent` per test whose rules are a table and which answers every call with an engine error once told to fail; `Turnstile.Test.Clock.set/1` fixes the moment the calling process's port calls read; `queries/2` and `changes/1` count the SQL and the change events a function produced; `poll/2` is the one deadline loop; `settle/0` settles the configured adapter or answers `:none`.
- Test support, compiled and never published: the neutral fixture, `Turnstile.Fixture`, with accounts, folders, items, and memberships, and its `World`, which is what the suite runs against here.

This package's `lib` depends on `ecto`, `nimble_options`, and `stream_data`, the last because the generators are the product an adopter runs; `ecto_sql` and `postgrex` serve its own tests only, and Boundary checks that no call from `lib` reaches them. The Postgres cluster the tests raise and the schema-dump task live in `turnstile_dev`.

## Configuring an application

```elixir
config :turnstile,
  adapter: MyApp.Adapter,
  clock: &DateTime.utc_now/0,
  caps: [policy_content_bytes: 65_536]
```

The adapter is a module or a `{module, keyword}` pair, the keyword validated by the adapter's `options_schema/0`. Every environment fact beyond `now` is the caller's to supply in `opts`, under `env:`, and an operation id under `operation_id:`; the port makes one when the caller does not.
